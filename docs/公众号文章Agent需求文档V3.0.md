## 1. 项目概述

### 1.1 项目背景

在科技/AI 垂直领域，热点内容时效性强、更新速度快。目前公众号内容生产依赖人工完成"选题 → 调研 → 撰写 → 排版 → 发布"全流程，存在以下痛点：

- **选题费时**：需要人工浏览微信、抖音等多个平台寻找热点，效率低且容易遗漏
- **生产周期长**：从发现热点到成稿往往需要数小时，错失流量窗口期
- **产能瓶颈**：无法批量、稳定地产出内容，日更难度大
- **排版重复**：固定模板的排版操作占用大量重复劳动

### 1.2 项目目标

构建一套**公众号文章自动化 Agent 系统**，实现：

1. **自动抓取**科技/AI 垂直领域热点内容（微信热文、抖音热点），构建当日热点池
2. **自动归纳**热点主题，生成选题建议与内容摘要
3. **自动成稿**：基于选定热点，按照**人工设计并入库的模板**由 AI 生成符合公众号调性的文章
4. **自动推送**：将生成的稿件自动写入公众号平台草稿箱
5. **人工兜底**：所有稿件必须经人工审核通过后方可发布，确保内容质量与合规
6. **数据闭环**：发布后回流阅读/互动数据，持续校准评分公式与选题方向（V3.0 新增）

**核心原则：机器负责"采、编、排"，人负责"审、发"**，兼顾效率与安全。同时**一切自动化行为受熔断机制约束**，杜绝失控与无限重复；**一切数据采集受合规边界约束**，杜绝侵权与过度留存（V3.0 强化）。

### 1.3 项目范围

**本期包含（In Scope）：**

- 微信热文、抖音热点两类数据源抓取（支持第三方 API 授权 / 公开页面爬取双模式）
- 热点聚合、聚类、热度评分与选题推荐
- 模板的**人工设计、入库、选择**；基于模板的 AI 文章生成（标题、摘要、正文）
- 通过浏览器自动化将稿件写入公众号草稿箱
- 人工审核操作台（待审核 / 通过 / 驳回 / 修改 / **在线编辑**）
- **控制面板**：数据源、抓取范围、抓取字段、抓取量、频率、评分参数、调度任务等可视化配置
- **本地知识库**：热文留存与定期清理（含**合规清理**：存储期限、一键删稿）
- **断点保留与流程回溯**
- **发布效果数据回流**：发布后抓取已发布文章数据并回写（V3.0 新增）
- **运营看板与告警**：核心运营指标可视化与异常告警（V3.0 新增）

**本期不包含（Out of Scope）：**

- 公众号定时群发/自动发布（仅生成草稿，发布由人工执行）
- 多公众号矩阵管理
- 移动端 App / 小程序端操作界面
- 基于回流数据的自动选题调优算法（V3.0：一期仅回写与展示，自动校准二期实现）

## 2. 名词解释

| 名词 | 说明 |
|------|------|
| Agent | 自动化智能体，本系统中指代整个"抓取-分析-生成-推送-回流"流水线 |
| 热点池 | 当日抓取、去重、评分后的热点集合 |
| 热点归纳 | 对热点进行聚类与主题提炼，产出选题建议 |
| 模板 | 文章的结构化写作框架（标题风格、章节结构、字数、口吻等），**人工设计后入库管理** |
| 文章结构 | 模板内正文的章节组成方案（如"事件回顾+影响分析+观点"），可在模板中设计并选择 |
| 草稿 | 微信公众号平台草稿箱中的图文消息草稿，可编辑未发布 |
| 浏览器自动化 | 通过程序模拟浏览器操作（登录、填表、点击），替代人工完成平台操作 |
| 熔断机制 | 当某环节失败/重试次数超过阈值时，自动停止该环节并启用规则兜底，防止无限重复 |
| 断点 | 流程中已完成的环节状态快照，用于失败后断点续跑与全流程回溯 |
| 控制面板 | 系统配置中心，提供数据源、抓取参数、评分公式、模板、调度、账号等设置入口 |
| 本地知识库 | 历史热文与已生成稿件的沉淀库，供选题参考与再创作 |
| top_n | 每次抓取的热点条数配置（控制面板可调，默认 20 条） |
| **归一化** | 将不同量纲的原始热度值映射到同一可比区间（如排名百分位 0~1）后再参与加权（V3.0 新增） |
| **空窗场景** | 当日热点为空、抓取失败或无可推送稿件等非正常流程的统称（V3.0 新增） |
| **效果数据回流** | 发布后抓取文章阅读/点赞/在看/转发等数据并回写系统的闭环能力（V3.0 新增） |
| **运营看板** | 以可视化方式展示抓取量、生成数、审核滞留、发布效果等核心指标的页面（V3.0 新增） |

│              ⑥ 控制面板（配置中心）＋ ⑨ 运营看板              │
│   数据源/抓取范围/抓取字段/抓取量/频率/评分参数/模板/调度/账号   │
└─────────────────────────────────────────────────────────────┘
                │ 读取配置下发
                ▼
┌─────────────────────────────────────────────────────────────┐
│                        调度中心（Scheduler）                 │
│          定时任务（人工设计 cron） / 手动触发 / 失败重试       │
└─────────────────────────────────────────────────────────────┘
                │
                ▼
┌──────────────────────┐   ┌──────────────────────┐
│  ① 热点抓取模块       │   │  ② 热点分析归纳模块   │
│  · 微信热文（API/爬虫）│──▶│  · 清洗与去重         │
│  · 抖音热点（API/爬虫）│   │  · 聚类与主题提炼     │

│  · 合规采集（元数据）  │   │    跨平台归一化）      │
│  · 写入热点池+知识库  │   │  · 归纳报告           │
└──────────────────────┘   └──────────────────────┘
                                          │
                                          ▼
┌──────────────────────┐   ┌──────────────────────┐
│  ③ 文章生成模块       │   │  ④ 草稿推送模块       │
│  · 模板/结构选择（可选）│──▶│  · 公众号登录管理     │
│  · LLM 生成（标题/    │   │  · 草稿自动创建       │
│    正文/摘要）        │   │  · 结果回执           │
│  · 质量校验（含事实性）│   │  · 页面改版容错       │
└──────────────────────┘   └──────────────────────┘
                                          │
                                          ▼
┌─────────────────────────────────────────────────────────────┐
│  ⑤ 人工审核与发布模块（审核操作台，支持在线编辑）             │
│  待审核 → 通过（人工发布）/ 驳回（附原因）/ 修改/ 在线编辑     │
└─────────────────────────────────────────────────────────────┘
                                          │ 人工发布后
                                          ▼
┌─────────────────────────────────────────────────────────────┐
│  ⑧ 效果数据回流模块（V3.0）                                   │
│  抓取已发布文章数据 → 回写 article_stats → 校准评分/选题      │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  ⑦ 本地知识库（数据资产）                                    │

全局横切：熔断机制（超限即停 + 规则兜底）｜ 断点保留（环节状态快照，可续跑、可回溯）
          ｜ 合规约束（仅存元数据、存储期限、一键删稿）｜ 空窗兜底（4.4）

### 3.1 技术架构分层

| 层 | 组件 | 说明 |
|----|------|------|
| 接入层 | 数据源适配器（API 模式 / 爬虫模式） | 统一输出标准结构化数据，模式可切换；**合规过滤在此层执行（仅保留元数据字段）** |
| 服务层 | 分析引擎、生成引擎、推送引擎、回流引擎、知识库服务 | 核心业务逻辑，可独立部署/调用 |
| AI 层 | LLM 调用服务 | 统一封装提示词管理与模型调用，模型可配置（默认通义千问 qwen3.6-plus）；**内置事实性约束提示词** |
| 数据层 | 本地数据库 + 知识库 | SQLite（轻量起步）/ MySQL（规模化后） |
| 自动化层 | Playwright | 浏览器自动化，操作用户公众号平台；**选择器集中管理 + 失败截图** |
| 调度层 | APScheduler / 系统计划任务 | 人工设计的定时任务 |
| 配置层 | 控制面板（轻量 Web） | 全部运行参数可视化配置 |
| **观测层** | **运营看板 + 告警（V3.0）** | 核心指标可视化，异常告警（熔断/连续失败/滞留超时） |

## 4. 核心业务流程

### 4.1 主流程（端到端）

```
[每日 08:00 定时触发（时间可人工配置）]
        │
        ▼
┌─ ① 热点抓取 ──────────────────────────────────────────┐
│ 微信热文：优先第三方 API（用户已授权），无权限则爬虫兜底   │
│ 抖音热点：优先第三方 API（用户已授权），无权限则爬虫兜底   │
│ 按控制面板配置：数据源多选 / 抓取范围 / 抓取字段 / 抓取量  │
│ 合规采集：仅保留标题/摘要/链接/热度等元数据               │
│ 写入热点池 + 同步沉淀至本地知识库                        │
└───────────────────────────────────────────────────────┘
        │ 若热点池为空 → 走空窗兜底（4.4）
        ▼
┌─ ② 热点分析归纳 ──────────────────────────────────────┐
│ 清洗：去重、去广告、去无关内容                           │
│ 聚类：按主题关键词聚合（如"大模型""自动驾驶""芯片"）      │
│ 评分：先单平台归一化（排名百分位），再按参数公式加权       │
│ 产出：当日热点归纳报告（Top 主题 + 建议选题 + 简述）      │
└───────────────────────────────────────────────────────┘
        │
        ▼
┌─ ③ 文章生成 ──────────────────────────────────────────┐
│ 从归纳报告选择主题（默认 Top1，可人工指定）               │
│ 人工/自动选择模板与文章结构（加载模板时可随时切换）        │
│ 组装 Prompt（含事实性硬约束：禁止编造，标注【待核实】）    │
│ 调用 LLM（默认 qwen3.6-plus）→ 生成                     │
│ 校验：字数 / 结构 / 敏感词 / 事实性                     │
│ 校验失败 → 重新生成，受熔断机制约束（最多 N 次后规则兜底）  │
└───────────────────────────────────────────────────────┘
        │
        ▼
┌─ ④ 草稿推送 ──────────────────────────────────────────┐
│ 浏览器自动化登录公众号平台（session 复用 / 扫码重登）      │
│ 新建图文 → 填入标题 / 作者 / 正文 → 保存草稿             │
│ 记录草稿链接与状态；失败自动重试，超限触发熔断            │
│ 页面改版容错：选择器集中管理，失败截图 + 标记人工修复      │
└───────────────────────────────────────────────────────┘
        │
        ▼
┌─ ⑤ 人工审核与发布 ────────────────────────────────────┐
│ 审核操作台：热点归纳 + 生成稿件 + 草稿链接               │
│ 小修 → 审核台在线编辑（富文本）→ 保存更新草稿            │
│ 大改 → 驳回附原因，Agent 重新生成（受熔断约束）          │
│ 通过 → 人工前往公众号平台手动发布（Agent 不代发）        │
└───────────────────────────────────────────────────────┘
        │ 人工发布后
        ▼
┌─ ⑧ 效果数据回流（V3.0）──────────────────────────────┐
│ 按配置频率（发布后第 1/3/7 天）抓取已发布文章数据         │
│ 回写 article_stats，沉淀知识库，运营看板展示             │
│ 供人工复盘选题，二期用于自动校准评分权重                 │
└───────────────────────────────────────────────────────┘
```

**每个环节执行前写入断点快照；任一环节失败后可断点续跑，全过程日志可回溯。**

### 4.2 状态机（稿件生命周期）

```
抓取中 → 已入库 → 分析中 → 已归纳
                         │
                         ▼
                    生成中 → 已生成 → 推送中 → 已推送(草稿)
                                         │
                                         ▼
                                    待审核 ──通过──▶ 待发布（人工发布）──▶ 已发布 ──▶ 已回流
                                       │  │
                                       │  └─驳回──▶ 重新生成（熔断约束）
                                       ├─修改意见──▶ 待人工编辑（V3.0：在线编辑）──▶ 已编辑 ──▶ 待审核
                                       └─在线编辑──▶ 已保存（更新草稿）──▶ 待审核
```

### 4.3 触发方式与定时任务

| 方式 | 说明 | 配置方式 |
|------|------|---------|
| 每日定时 | 默认 08:00 抓取、08:30 生成、09:00 推送草稿 | 控制面板以 cron 表达式自定义 |
| **人工设计定时任务** | 支持新增/修改/停用多个定时任务（如"每 6 小时抓取热点""每周一生成周报选题"） | 控制面板 → 定时任务管理，cron 可视化编辑 |
| 手动一键触发 | 操作台"立即运行"，可指定只跑某环节 | 操作台按钮 |
| 失败自动重试 | 失败自动重试，次数受熔断机制约束 | 全局配置 |

### 4.4 空窗场景与兜底处理（V3.0 新增）

系统必须显式定义以下"非正常但必然会发生"的场景，避免流程空转或报错堆积：

| 场景 | 判定条件 | 处理策略 |
|------|---------|---------|
| 热点池为空 | 所有数据源抓取 0 条，或清洗去重后为 0 | 当日流程**立即终止**，发送"今日无热点"通知，不执行生成/推送 |
| 单源抓取失败 | 某数据源连续失败 N 次（受熔断约束） | 仅使用可用数据源继续；全部失败按热点池为空处理 |
| 无合格稿件 | 生成/校验连续失败，热点进入黑名单且无备选选题 | 当日流程终止，汇总失败原因，通知人工介入 |
| 审核滞留超时 | 稿件处于待审核超过 X 小时（默认 24h，可配） | 每日运营看板高亮 + 推送提醒，不自动处理（人审原则） |
| 草稿推送被风控 | 推送连续失败且熔断触发 | 停止自动推送，切换半自动方案 B，通知人工 |
| 回流数据缺失 | 已发布文章抓取不到数据（被删/接口异常） | 记录失败但不阻断其他流程，次日重试 |

> 空窗原则：**宁可当日不发，不可错发**。所有空窗终止均记录 run_logs，可在控制面板回溯原因。

## 5. 详细功能需求

### 5.1 热点抓取模块

#### 5.1.1 数据源接入模式（双模式）

| 模式 | 说明 | 前提 |
|------|------|------|
| **API 模式（优先）** | 调用第三方数据服务 API（如新榜、清博、抖音开放平台等） | 用户在控制面板**自行输入 API 授权信息**（key/secret/账号凭据），系统保存并验证可用性 |
| **爬虫模式（兜底）** | 对公开页面进行抓取（Playwright/requests） | 无需授权；受频率限制与反爬约束 |

**权限策略**：API 授权信息**完全由用户自行输入与维护**。系统不代为申请权限；未配置 API 或验证失败时，自动降级为爬虫模式，并给出提示。

#### 5.1.2 微信热文抓取

| 需求项 | 详细说明 |
|--------|---------|

#### 5.1.3 抖音热点抓取

#### 5.1.4 数据清洗与入库

- 统一字段格式，写入 `hot_topics` 表，**同时沉淀至本地知识库**
- 记录抓取时间、数据源、抓取模式（API/爬虫），支持回溯

#### 5.1.5 数据合规与版权边界（V3.0 新增）

本模块是系统合规底线，所有数据采集与存储必须遵守：

| 约束项 | 规则 | 实现 |
|--------|------|------|
| **仅存元数据** | 抓取内容**不存储正文全文**，仅保留标题、摘要、链接、作者、热度、发布时间等元数据 | 接入层剥离正文，`hot_topics` 表无正文字段；生成稿件引用的原文素材使用后即弃 |
| **存储期限** | 热点数据默认保留 **30 天**（控制面板可配），到期自动清理 | 定时清理任务 + 清理审计日志 |
| **一键删稿** | 收到侵权投诉/权利人通知时，支持按链接**一键删除**热点记录 | 操作台提供"删除"入口，删除动作写入 `kb_clean_logs` |
| **用途限制** | 抓取内容**仅作选题参考**，不得整文转载、二次分发、商用 | 归纳报告与生成稿件均附来源链接，生成时提示"基于热点改写，非转载" |
| **频率合规** | 爬虫模式严格遵守目标平台访问频率限制，限速抓取 | 请求间隔随机化、单日抓取上限（默认 500 次，可配） |
| **授权合规** | API 模式凭用户自填授权；爬虫模式仅访问公开页面，不绕过登录/验证码 | 适配器层校验，违规模式自动降级并提示 |
| **内容合规** | 涉及个人信息（作者昵称等）仅内部使用，不外泄、不展示 | 日志脱敏，展示端匿名化 |

### 5.2 热点分析归纳模块

| 需求项 | 详细说明 |
|--------|---------|
| 聚类 | 基于关键词/LLM 语义将热点聚合成主题簇（如"大模型发布""算力芯片"） |
| 主题提炼 | 每个主题簇输出：主题名、相关热点数、代表热点、热度合计 |
| 热度评分 | 评分公式**先单平台归一化，再基于控制面板参数动态加权**（详见 5.2.1） |
| 产出报告 | 当日热点归纳报告：Top5 主题 + 建议选题角度 + 一句话简述（JSON + Markdown 双份） |

#### 5.2.1 热度评分公式（参数化 + 跨平台归一化，V3.0 修订）

> **背景问题**：微信阅读量通常为千~十万级，抖音热度分为万~百万级，量纲差异极大。若直接相乘加权，数值大的平台将完全主导评分，来源权重形同虚设。故 V3.0 引入归一化。

```
第一步（单平台归一化，可选方式，控制面板配置）：
  方式 A（默认）排名百分位：rank_pct = 该热点在该平台当日抓取集合中的热度排名 / 集合总数（0~1）
  方式 B 对数归一化：log_norm = log10(1 + 原始热度) / log10(1 + 该平台当日最大值)
  方式 C Min-Max：(原始热度 - 当日最小值) / (当日最大值 - 当日最小值)

第二步（综合热度）：
综合热度 = Σ(来源权重 × 单平台归一化热度) × 时效衰减因子 × 领域相关度 × 抓取量系数

其中：
  · 单平台归一化热度：第一步的输出（0~1，量纲已对齐）
  · 来源权重         ：微信 / 抖音各自的权重系数（控制面板可调，默认 0.6 / 0.4；
                        若用户在控制面板新增/停用数据源，权重自动归一化重算）
  · 时效衰减因子     ：按抓取时间与发布时间差衰减，半衰期可配置（默认 24h）
  · 领域相关度       ：与领域关键词表的匹配度（命中数 / 长度），0~1
  · 抓取量系数       ：实际抓取条数与配置抓取量的归一化比，防样本不均
```

> 评分公式参数（归一化方式、来源权重、半衰期、权重计算方式等）全部在控制面板可视化调整，调整即时生效并记录版本。归一化方式变更时，历史稿件评分不回算（仅影响新评分），避免数据混乱。

### 5.3 文章生成模块

#### 5.3.1 模板管理（人工设计 → 数据库保存）

| 需求项 | 详细说明 |
|--------|---------|
| 设计方式 | 模板由**人工设计**（JSON 结构化定义），在控制面板的模板编辑器中填写 |
| 入库 | 设计完成后保存至数据库 `templates` 表，支持预览、复制、停用、删除 |
| 文章结构 | 模板内可设计多种"结构方案"（如"事件回顾式""观点评论式""盘点清单式"），每个模板可包含多个结构方案，生成时可选择 |
| 生成时选择 | 运行生成流程时，**加载模板的步骤中人工/自动可选**：选择模板 + 选择结构方案，可中途切换（见 5.3.3） |

模板 JSON 示例：

```json
{
  "template_id": "tpl_ai_news_v1",
  "name": "AI 领域热点解读",
  "scene": "热点解析类",
  "structures": [
    {
      "structure_id": "s1",
      "name": "事件回顾式",
      "sections": [
        {"key": "title", "desc": "标题，含核心关键词，20字内，生成3个候选"},
        {"key": "lead", "desc": "导语 80~120 字，点明热点+读者价值"},
        {"key": "body", "desc": "正文 1200~1800 字，分 3~4 小节：事件回顾/影响分析/观点"},
        {"key": "quote", "desc": "金句 1 句，可引用行业观点"},
        {"key": "cta", "desc": "结尾引导 50~80 字，引导点赞/转发/关注"}
      ]
    },
    {
      "structure_id": "s2",
      "name": "盘点清单式",
      "sections": [
        {"key": "title", "desc": "标题，如《2026 值得关注的 5 大 AI 事件》"},
        {"key": "lead", "desc": "导语说明盘点背景"},
        {"key": "body", "desc": "正文按条目盘点，每条 150~250 字"},
        {"key": "cta", "desc": "结尾引导互动"}
      ]
    }
  ],
  "style": {"tone": "专业但不晦涩", "persona": "科技观察者", "ban_words": ["绝对", "最", "第一"]}
}
```

#### 5.3.2 生成流程（V3.0 增加事实性硬约束）

1. 选定主题（默认 Top1，可人工指定）
2. **选择模板 + 文章结构方案**（默认模板由控制面板指定，运行时可更改）
3. 加载模板 + 热点数据（标题/摘要/链接，**不加载正文全文**，合规约束）+ 知识库相关素材（可选：LLM 补充背景）
4. 组装 Prompt，**必须包含以下事实性硬约束指令**：
   - 只基于提供的热点事实与素材写作，不得编造
   - **关键数字、人名、时间若素材中未提供，禁止编造**；应写"据公开报道"并留待人工核实
   - 正文末尾自动生成"信息来源"列表（引用抓取到的链接）
5. 调用 LLM 生成（默认通义千问 qwen3.6-plus，模型可在控制面板切换）
6. 结构化解析输出，保存至 `articles` 表

#### 5.3.3 质量校验与熔断（防无限重复）

| 校验项 | 规则 | 不通过处理 |
|--------|------|-----------|
| 字数 | 正文在模板区间 ±20% | 重新生成（受熔断约束） |
| 结构 | 各章节齐全 | 重新生成（受熔断约束） |
| 敏感词 | 命中违禁词表 | 人工标记，转审核拦截 |
| **事实性（V3.0 新增）** | 正文中的数字/专有名词/时间是否可在热点原文上下文或素材中溯源；无法溯源的必须带【待核实】标记 | 未标记的不可溯源项 → 自动追加【待核实】；带标记的不阻断，提示人工 |
| 事实性 | 含"据/报道"等来源标识提示人工核实 | 仅提示，不阻断 |

**熔断规则（全局）**：

- 单次生成失败重试上限：**默认 3 次**（控制面板可调）
- 超过上限：**停止自动重试，触发规则兜底** —— 自动标记该稿件为"生成失败"，记录失败原因，改由**人工指定调整方向后重试**或采用"备选结构方案/备选模板"降级生成一次
- 同一热点累计生成失败 ≥ 5 次：该热点自动进入黑名单，当日不再尝试

### 5.4 草稿推送模块（关键：个人订阅号方案）

| 登录方式 | 首次：启动浏览器打开 mp.weixin.qq.com，人工扫码登录；登录后保存 `storage_state.json` 复用会话 |

| 结果回执 | 成功：记录草稿链接与创建时间；失败：截图留证 + 标记推送失败，重试受熔断约束 |
| 风控保护 | 单日草稿上限（默认 5 篇）、操作间隔随机化（2~5 秒）、失败即停 |
| **页面改版容错（V3.0 新增）** | 见下方专项说明 |

**页面改版容错专项（V3.0 新增）** —— mp.weixin.qq.com 页面改版是必然事件，必须提前设计：

| 措施 | 说明 |
|------|------|
| 选择器集中管理 | 所有页面元素定位（XPath/CSS）集中于独立配置文件 `selectors.yaml`，**不散落在业务代码中**；页面改版时只需改配置 |

| 熔断配合 | 检测到页面改版类失败（选择器全部失效）时**立即停止重试**，转人工处理，避免账号风控 |
| 版本提醒 | 修复选择器后更新 `selectors.yaml` 版本号，变更记录可回溯 |

**备选/兜底方案**：

| 方案 | 说明 | 适用 |
|------|------|------|
| A. Playwright 自动化（主方案） | 全自动创建草稿 | 日常使用 |
| B. 半自动粘贴 | Agent 生成内容 → 人工粘贴到草稿箱 | 自动化被风控/页面改版待修时兜底 |
| C. 升级认证 | 升级为认证订阅号/服务号，改用官方 API | 长期演进方向，接口稳定 |

### 5.9 发布效果数据回流（V3.0 新增）

> **背景**：V2.0 流程止于"发布"，缺少发布后数据反馈，导致热度评分公式与选题方向无法验证和迭代。V3.0 补上闭环的最后一块。

| 需求项 | 详细说明 |
|--------|---------|
| 数据来源 | 已发布文章的阅读数、点赞数、在看数、转发数（通过公众号后台页面爬取 / 第三方统计 API，沿用双模式） |
| 抓取时机 | 发布后第 **1 / 3 / 7 天**各抓取一次（控制面板可配），覆盖阅读曲线早期峰值与稳定期 |
| 数据落库 | 回写 `article_stats` 表（按文章 + 日期），并沉淀至知识库 |
| 展示 | 运营看板展示每篇文章的流量表现，与选题/评分对照 |
| 用途 | ① 人工复盘选题质量；② 二期基于回流数据**自动校准**评分公式权重与选题模型（本期仅回写与展示，自动校准列为二期） |
| 失败处理 | 抓取失败记录日志，次日重试；不阻断其他流程（遵守空窗兜底原则） |

### 5.10 运营看板与告警（V3.0 新增）

| 看板模块 | 指标 | 说明 |

## 7. 数据模型设计（核心表）

```sql
-- 热点表（热点池 + 知识库留存；合规约束：仅元数据，无正文全文）
CREATE TABLE hot_topics (
  id INTEGER PRIMARY KEY,
  source TEXT NOT NULL,              -- wechat / douyin
  fetch_mode TEXT,                   -- api / crawler
  title TEXT NOT NULL,
  url TEXT,
  platform_hot REAL,
  author TEXT,
  summary TEXT,                      -- 摘要（非全文）
  category TEXT,
  heat_score REAL,                   -- 综合热度（归一化后）
  rank_pct REAL,                     -- 单平台归一化值（V3.0）
  fetch_date TEXT NOT NULL,
  expired_at TEXT,                   -- 合规存储期限（V3.0，默认抓取日+30天）
  deleted INTEGER DEFAULT 0,         -- 一键删稿软删除（V3.0）
  created_at TEXT DEFAULT (datetime('now'))
);

-- 稿件表
CREATE TABLE articles (
  id INTEGER PRIMARY KEY,
  topic_id INTEGER REFERENCES hot_topics(id),
  template_id TEXT NOT NULL,
  structure_id TEXT,                 -- 选用的文章结构方案
  title TEXT NOT NULL,
  lead TEXT, body TEXT, quote TEXT, cta TEXT,
  status TEXT DEFAULT 'generated',   -- generated/pushed/pending_review/approved/edited/published/backfilled
  draft_url TEXT,
  reject_reason TEXT,
  fact_notes TEXT,                   -- 【待核实】标记记录（V3.0）
  fail_count INTEGER DEFAULT 0,      -- 失败次数（熔断计数）
  published_at TEXT,                 -- 人工发布确认时间（V3.0）
  created_at TEXT DEFAULT (datetime('now'))
);

-- 发布效果回流表（V3.0 新增）
CREATE TABLE article_stats (
  id INTEGER PRIMARY KEY,
  article_id INTEGER NOT NULL REFERENCES articles(id),
  read_count INTEGER,                -- 阅读数
  like_count INTEGER,                -- 点赞数
  share_count INTEGER,               -- 转发数
  favorite_count INTEGER,            -- 在看/收藏数
  stat_date TEXT NOT NULL,           -- 统计日期
  fetched_at TEXT DEFAULT (datetime('now')),
  UNIQUE(article_id, stat_date)      -- 同文同日只留一条
);

-- 模板表（人工设计入库）
CREATE TABLE templates (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  definition TEXT NOT NULL,          -- JSON（含 structures 数组）
  enabled INTEGER DEFAULT 1,
  updated_at TEXT
);

-- 配置表（控制面板，含评分参数/归一化方式/合规/回流/告警配置）
CREATE TABLE configs (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,               -- JSON
  updated_at TEXT,
  updated_by TEXT
);

-- 定时任务表（人工设计）
CREATE TABLE schedules (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  cron TEXT NOT NULL,
  actions TEXT NOT NULL,             -- 要执行的环节
  enabled INTEGER DEFAULT 1
);

-- 断点/运行日志表
CREATE TABLE run_logs (
  id INTEGER PRIMARY KEY,
  run_id TEXT NOT NULL,              -- 一次完整流程的 ID
  stage TEXT NOT NULL,               -- fetch/analyze/generate/push/review/backfill
  status TEXT NOT NULL,              -- success/failed/checkpoint
  detail TEXT,
  started_at TEXT, finished_at TEXT
);

-- 知识库清理日志表（含合规期限清理/一键删稿记录）
CREATE TABLE kb_clean_logs (
  id INTEGER PRIMARY KEY,
  topic_id INTEGER,
  clean_type TEXT,                   -- retention/dup/outdated/low_value/manual
  reason TEXT,
  cleaned_at TEXT
);
```

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 公众号平台风控（自动化操作被检测） | 账号受限/封禁 | 频率控制、间隔随机化、失败即停、熔断、保留人工兜底方案 B |
| 数据源反爬/接口变更 | 抓取失效 | 适配器化 + API/爬虫双模式互备；API 授权由用户维护 |
| **抓取合规/版权风险（V3.0 新增）** | 侵权投诉/平台封禁 | **仅存元数据不存正文全文、30 天存储期限、一键删稿机制、限速抓取、用途限制**（5.1.5） |
| **LLM 幻觉编造（V3.0 新增）** | 事实错误损害公信力/违规 | **事实性硬约束提示词 + 不可溯源项强制【待核实】标记 + 人工审核兜底**（5.3.2/5.3.3） |
| **公众号页面改版（V3.0 新增）** | 推送模块瘫痪 | **选择器集中管理、启动自检、失败截图、熔断即停、半自动方案 B 兜底**（5.4） |
| **评分量纲失真（V3.0 新增）** | 选题偏离真实热点 | **单平台归一化后再加权，归一化方式可配置**（5.2.1） |
| LLM 生成质量不稳定 | 稿件返工 | 强模板约束 + 质量校验 + 驳回重生成 + 熔断防无限循环 |
| 自动化无限重复（死循环） | 资源浪费/异常堆叠 | **全局熔断机制**：重试上限 + 超限规则兜底 + 热点黑名单 |
| 内容合规风险 | 违规处罚 | 强制人工审核后发布；敏感词拦截；热点仅参考不转载 |
| 知识库膨胀 | 存储膨胀/检索噪音 | 定期清理策略（合规期限/去重/过时/低价值）+ 清理日志可回溯 |
| session 过期/扫码障碍 | 推送中断 | 会话有效期检测 + 登录提醒机制 |
| 配置误操作 | 抓取异常/评分失真 | 配置变更日志 + 参数版本记录 + 默认值保护 |
| **空窗误判（V3.0 新增）** | 当日漏发/流程空转 | 空窗场景显式定义 + 终止即通知 + run_logs 可回溯（4.4） |

## 11. 验收标准

1. **抓取**：按控制面板配置（数据源多选、抓取范围、字段、量、频率）成功抓取并入库，API 未授权时自动降级爬虫且数据完整
2. **合规（V3.0）**：知识库中**不存在正文全文**；超期热点自动清理且有日志；一键删稿可生效并留痕
3. **归纳**：输出热点归纳报告，评分结果随评分参数调整而正确变化；**同一热点在微信/抖音的评分经归一化后可比（调整权重可明显改变排序）**
4. **生成**：模板可由人工设计并保存入库；生成时可选择模板与结构方案；稿件结构完整、字数达标、无敏感词；**正文不可溯源数字/专名带【待核实】标记或来自素材上下文**
5. **熔断**：人为制造连续失败，验证重试到上限后自动停止并按规则兜底（不无限重复）
6. **推送**：稿件自动出现在草稿箱，标题/正文格式正确，记录草稿链接；**模拟选择器失效时自动截图、停止重试并标记"需人工修复"**
7. **审核**：操作台可查看、通过、驳回、**在线编辑**；驳回后重新生成且受熔断约束；**在线编辑保存后草稿箱同步更新**
8. **知识库**：热文留存完整（仅元数据）；触发清理策略后合规/重复/过时/低价值内容被清理且有日志
9. **断点**：模拟流程中断后重启，可从断点续跑，全链路可回溯
10. **空窗（V3.0）**：模拟热点池为空，流程正确终止并发送通知，不生成不推送
11. **回流（V3.0）**：发布后文章阅读/互动数据可回写并在运营看板展示
12. **看板与告警（V3.0）**：运营看板指标正确展示；触发熔断/滞留/空窗时告警送达配置渠道
13. **稳定**：连续运行 7 天无人工干预（除审核与扫码外）全流程正常
