# 公众号文章自动化 Agent 系统 — 开发工单（V1.0）

| 文档信息 | 内容 |
|---------|------|
| 关联需求 | PRD V3.0（`docs/公众号文章Agent需求文档V3.0.md`） |
| 工单版本 | V1.0（2026-08-31） |
| 开发模式 | 单人兼职开发 |
| 总估时 | 约 36~40 个工作日（按兼职折算 5~6 周，含 POC） |

---

## 0. 角色定义（"谁"）

| 角色 | 代号 | 说明 |
|------|------|------|
| **开发者** | `DEV` | 你本人，承担全部编码与实现 |
| **人工配合** | `HUM` | 你本人，但必须"人在场"完成的操作（扫码、审核、发布、设计模板、填授权） |
| **Agent 系统** | `AGT` | 系统自动执行的任务（验证/运行环节） |
| **外部依赖** | `DEP` | 需申请/购买/配置的第三方资源（LLM Key、数据源 API、通知渠道） |

> 单人项目，`DEV` 与 `HUM` 是同一人，但**区分开有实际意义**：`HUM` 工单是"必须你停下别的事来操作"的节点，用于规划你的时间；`AGT` 工单验收时全自动跑，用于验证"无人值守"目标。

## 2. 详细工单

### S0 项目骨架（先决，做完才能跑其他）

**S0-01 工程初始化**
- 负责人：`DEV`
- 内容：`pyproject.toml`、venv、依赖安装（fastapi/uvicorn/playwright/apscheduler/openai 兼容库等）、目录结构、`.env.example`
- 产出：可 `pip install -e .` 的工程
- 依赖：无
- 验收：`python -c "import fastapi, playwright"` 通过

**S0-02 数据库层**
- 负责人：`DEV`
- 内容：按 PRD 第 7 章建 `schema.sql`（hot_topics/articles/article_stats/templates/configs/schedules/run_logs/kb_clean_logs 共 8 表）+ `core/db.py` 连接与初始化
- 产出：`init_db()` 一键建库建表
- 依赖：S0-01
- 验收：运行后 `data/app.db` 生成，8 张表齐全

**S0-03 配置中心**
- 负责人：`DEV`
- 内容：`config.py` 加载 configs 表 + 环境变量 + 默认值兜底；密钥类配置仅从 `.env` 读取
- 产出：`get_config(key)` 统一入口
- 依赖：S0-02
- 验收：配置可读写、变更记录版本号

**S0-04 横切组件**
- 负责人：`DEV`
- 内容：熔断器 `circuit_breaker.py`（重试上限/规则兜底/热点黑名单）、断点 `checkpoint.py`、日志 `logger.py`（落 run_logs）
- 产出：三个可 import 的组件 + 单元测试
- 依赖：S0-02
- 验收：单测通过；熔断器在 N 次失败后正确停止并记录

**S0-05 FastAPI 启动骨架**
- 负责人：`DEV`
- 内容：`main.py` 启动时建表 + 注册路由 + 调度器占位；`/health` 健康检查
- 产出：`uvicorn app.main:app` 可启动
- 依赖：S0-02~04
- 验收：服务启动、健康检查 200

### POC 技术验证（关键路径前移，可与 S0 并行）

**POC-01 推送出口验证** ⭐ 最关键
- 负责人：`DEV` + `HUM`（需扫码一次）
- 内容：用最小脚本验证 Playwright 打开 mp.weixin.qq.com → 扫码登录 → 保存 session → 创建 1 条测试草稿
- 产出：可行性结论 + 登录/建稿最小代码
- 依赖：S0-01（仅需 venv）
- 验收：草稿箱出现测试草稿；或明确被风控拦截（此时定案切半自动方案 B）
- 结论影响：决定 M4 架构

**POC-02 数据入口验证**
- 负责人：`DEV`（+ `DEP` 可选：申请数据源 API）
- 内容：验证微信热文/抖音热点抓取——API 是否可用；爬虫兜底能否拿到结构化数据
- 产出：各数据源 20 条真实样本 + 抓取方式结论
- 依赖：S0-01
- 验收：拿到含标题/热度/链接的样本，字段完整

**POC-03 生成质量验证**
- 负责人：`DEV` + `DEP`（LLM Key） + `HUM`（评估）
- 内容：用附录 A 模板 + qwen3.6-plus 生成 1 篇样稿，人工按字数/结构/事实性评估
- 产出：样稿 + 质量评估结论
- 依赖：S0-01、LLM Key
- 验收：结构完整、字数达标、无严重事实错误

### M1 数据接入（1.5 周）

**M1-01 数据源抽象基类**
- 负责人：`DEV`
- 内容：`collectors/base.py` 定义统一接口（API 模式 / 爬虫模式双实现），合规过滤（仅元数据）在此层执行
- 产出：BaseCollector 抽象 + 双模式工厂
- 依赖：S0-02
- 验收：新增数据源只需实现一个接口

**M1-02 微信热文抓取器**
- 负责人：`DEV`（+ `HUM` 填授权，若走 API）
- 内容：`collectors/wechat.py` API 优先 + 爬虫兜底；领域关键词过滤；字段按配置勾选
- 产出：可运行的微信热文采集器
- 依赖：M1-01
- 验收：按配置抓取 top_n 条，入库 hot_topics

**M1-03 抖音热点抓取器**
- 负责人：`DEV`（+ `HUM` 填授权，若走 API）
- 内容：`collectors/douyin.py` API 优先 + 爬虫兜底；全榜过滤领域相关
- 产出：可运行的抖音热点采集器
- 依赖：M1-01
- 验收：按配置抓取，入库 hot_topics

**M1-04 清洗与合规入库**
- 负责人：`DEV`
- 内容：去重（MD5）/去广告/去标题党；写入 hot_topics + 知识库（**不含正文全文**）；记录 fetch_mode/expired_at
- 产出：清洗管线 + 入库模块
- 依赖：M1-02/03
- 验收：重复数据被去重；库中无正文字段；合规字段齐全

**M1-05 抓取配置接入面板**
- 负责人：`DEV`
- 内容：数据源多选、关键词表、字段勾选、抓取量、频率 → 写入 configs 表并生效
- 产出：抓取参数可视化配置
- 依赖：M1-04、S0-05
- 验收：改配置后重新抓取按新参数执行

### M2 分析归纳（4 天）

**M2-01 清洗去重器**
- 负责人：`DEV`
- 内容：`analyzer/cleaner.py` 标题相似去重、广告/标题党过滤
- 产出：cleaner 模块 + 单测
- 依赖：M1-04
- 验收：输入脏数据输出干净热点池

**M2-02 聚类与主题提炼**
- 负责人：`DEV`
- 内容：`analyzer/cluster.py` 关键词/LLM 语义聚类，输出主题簇（主题名/相关热点数/代表热点）
- 产出：cluster 模块
- 依赖：M2-01
- 验收：可聚出"大模型发布""算力芯片"类主题簇

**M2-03 归一化热度评分器**
- 负责人：`DEV`
- 内容：`analyzer/scorer.py` 单平台归一化（默认排名百分位）+ 参数化加权公式（来源权重/半衰期/相关度/抓取量系数）
- 产出：scorer 模块 + 公式单测
- 依赖：M2-01、S0-03
- 验收：同一热点微信/抖音评分可比；调权重排序正确变化

**M2-04 归纳报告生成**
- 负责人：`DEV`
- 内容：Top5 主题 + 建议选题 + 简述，JSON + Markdown 双份输出
- 产出：报告生成器
- 依赖：M2-02/03
- 验收：产出完整归纳报告，可直接供审核台展示

### M3 文章生成（5 天）

**M3-01 模板管理**
- 负责人：`DEV` + `HUM`（设计 1~2 套模板入库）
- 内容：`generator/templates.py` 模板 CRUD（含结构方案）、预览、复制、停用
- 产出：模板库管理模块 + 1~2 套示例模板
- 依赖：S0-02、S0-05
- 验收：模板可入库/编辑/切换结构方案

**M3-02 LLM 统一封装**
- 负责人：`DEV` + `DEP`（LLM Key）
- 内容：`generator/llm.py` OpenAI 兼容接口封装，模型/temperature/max_tokens 可配，默认 qwen3.6-plus
- 产出：`generate(prompt) -> str` 统一入口
- 依赖：S0-03
- 验收：切换模型配置后调用生效

**M3-03 提示词组装（含事实性约束）**
- 负责人：`DEV`
- 内容：`generator/prompt.py` 角色/任务/结构/字数/风格/示例组装；强制"禁止编造、不可溯源标【待核实】、末尾附信息来源"
- 产出：prompt 组装器
- 依赖：M3-02
- 验收：生成的 prompt 包含事实性硬约束段落

**M3-04 质量校验器**
- 负责人：`DEV`
- 内容：`generator/validator.py` 字数±20%/结构齐全/敏感词/事实性（不可溯源项自动标【待核实】）
- 产出：validator + 单测
- 依赖：M3-03
- 验收：四类校验项均可触发对应处理

**M3-05 生成编排与熔断集成**
- 负责人：`DEV`
- 内容：选定主题→选模板→生成→校验→重试（≤3 次）→超限规则兜底→热点黑名单（≥5 次）
- 产出：生成流水线 + 断点记录
- 依赖：M3-02~04、S0-04
- 验收：连续失败到上限后停止并按规则兜底

| 收尾 | 确认合规走查结论 | X-03 |

> 除上述节点外，系统应能连续运行无需人工干预。
