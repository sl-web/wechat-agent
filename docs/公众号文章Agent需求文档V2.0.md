## 1. 项目概述

### 1.1 项目背景

在科技/AI 垂直领域，热点内容时效性强、更新速度快。目前公众号内容生产依赖人工完成"选题 → 调研 → 撰写 → 排版 → 发布"全流程，存在以下痛点：

- **选题费时**：需要人工浏览微信、抖音等多个平台寻找热点，效率低且容易遗漏
- **生产周期长**：从发现热点到成稿往往需要数小时，错失流量窗口期
- **产能瓶颈**：无法批量、稳定地产出内容，日更难度大
- **排版重复**：固定模板的排版操作占用大量重复劳动

### 1.2 项目目标

构建一套**公众号文章自动化 Agent 系统**，实现：

1. **自动抓取**科技/AI 垂直领域热点内容（微信热文、抖音热点），构建当日热点池
2. **自动归纳**热点主题，生成选题建议与内容摘要
3. **自动成稿**：基于选定热点，按照**人工设计并入库的模板**由 AI 生成符合公众号调性的文章
4. **自动推送**：将生成的稿件自动写入公众号平台草稿箱
5. **人工兜底**：所有稿件必须经人工审核通过后方可发布，确保内容质量与合规

**核心原则：机器负责"采、编、排"，人负责"审、发"**，兼顾效率与安全。同时**一切自动化行为受熔断机制约束**，杜绝失控与无限重复。

### 1.3 项目范围

**本期包含（In Scope）：**

- 微信热文、抖音热点两类数据源抓取（支持第三方 API 授权 / 公开页面爬取双模式）
- 热点聚合、聚类、热度评分与选题推荐
- 模板的**人工设计、入库、选择**；基于模板的 AI 文章生成（标题、摘要、正文）
- 通过浏览器自动化将稿件写入公众号草稿箱
- 人工审核操作台（待审核 / 通过 / 驳回 / 修改）
- **控制面板**：数据源、抓取范围、抓取字段、抓取量、频率、评分参数、调度任务等可视化配置
- **本地知识库**：热文留存与定期清理
- **断点保留与流程回溯**

**本期不包含（Out of Scope）：**

- 公众号定时群发/自动发布（仅生成草稿，发布由人工执行）
- 多公众号矩阵管理
- 移动端 App / 小程序端操作界面

## 2. 名词解释

| 名词 | 说明 |
|------|------|
| Agent | 自动化智能体，本系统中指代整个"抓取-分析-生成-推送"流水线 |
| 热点池 | 当日抓取、去重、评分后的热点集合 |
| 热点归纳 | 对热点进行聚类与主题提炼，产出选题建议 |
| 模板 | 文章的结构化写作框架（标题风格、章节结构、字数、口吻等），**人工设计后入库管理** |
| 文章结构 | 模板内正文的章节组成方案（如"事件回顾+影响分析+观点"），可在模板中设计并选择 |
| 草稿 | 微信公众号平台草稿箱中的图文消息草稿，可编辑未发布 |
| 浏览器自动化 | 通过程序模拟浏览器操作（登录、填表、点击），替代人工完成平台操作 |
| 熔断机制 | 当某环节失败/重试次数超过阈值时，自动停止该环节并启用规则兜底，防止无限重复 |
| 断点 | 流程中已完成的环节状态快照，用于失败后断点续跑与全流程回溯 |
| 控制面板 | 系统配置中心，提供数据源、抓取参数、评分公式、模板、调度、账号等设置入口 |
| 本地知识库 | 历史热文与已生成稿件的沉淀库，供选题参考与再创作 |
| top_n | 每次抓取的热点条数配置（控制面板可调，默认 20 条） |

## 3. 总体架构

系统采用**模块化流水线架构**，共 7 大功能模块 + 1 项数据资产（本地知识库）：

```
┌─────────────────────────────────────────────────────────────┐
│                  ⑥ 控制面板（配置中心）                      │
│   数据源/抓取范围/抓取字段/抓取量/频率/评分参数/模板/调度/账号  │
└─────────────────────────────────────────────────────────────┘
                │ 读取配置下发
                ▼
┌─────────────────────────────────────────────────────────────┐
│                        调度中心（Scheduler）                 │
│          定时任务（人工设计 cron） / 手动触发 / 失败重试      │
└─────────────────────────────────────────────────────────────┘
                │
                ▼
┌──────────────────────┐   ┌──────────────────────┐
│  ① 热点抓取模块       │   │  ② 热点分析归纳模块   │
│  · 微信热文（API/爬虫）│──▶│  · 清洗与去重         │
│  · 抖音热点（API/爬虫）│   │  · 聚类与主题提炼     │
│  · 领域关键词过滤     │   │  · 热度评分（参数化）  │
│  · 写入热点池+知识库  │   │  · 归纳报告           │
└──────────────────────┘   └──────────────────────┘
                                          │
                                          ▼
┌──────────────────────┐   ┌──────────────────────┐
│  ③ 文章生成模块       │   │  ④ 草稿推送模块       │
│  · 模板/结构选择（可选）│──▶│  · 公众号登录管理     │
│  · LLM 生成（标题/    │   │  · 草稿自动创建       │
│    正文/摘要）        │   │  · 结果回执           │
│  · 质量校验           │   └──────────────────────┘
└──────────────────────┘
                                          │
                                          ▼
┌─────────────────────────────────────────────────────────────┐
│  ⑤ 人工审核与发布模块（审核操作台）                          │
│  待审核 → 通过（人工发布）/ 驳回（附原因）/ 修改意见          │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  ⑦ 本地知识库（数据资产）                                    │
│  热文留存 → 定期清理（主题重复 / 过时 / 低价值）→ 辅助选题     │
└─────────────────────────────────────────────────────────────┘

全局横切：熔断机制（超限即停 + 规则兜底）｜ 断点保留（环节状态快照，可续跑、可回溯）
```

### 3.1 技术架构分层

| 层 | 组件 | 说明 |
|----|------|------|
| 接入层 | 数据源适配器（API 模式 / 爬虫模式） | 统一输出标准结构化数据，模式可切换 |
| 服务层 | 分析引擎、生成引擎、推送引擎、知识库服务 | 核心业务逻辑，可独立部署/调用 |
| AI 层 | LLM 调用服务 | 统一封装提示词管理与模型调用，模型可配置（默认通义千问 qwen3.6-plus） |
| 数据层 | 本地数据库 + 知识库 | SQLite（轻量起步）/ MySQL（规模化后） |
| 自动化层 | Playwright | 浏览器自动化，操作用户公众号平台 |
| 调度层 | APScheduler / 系统计划任务 | 人工设计的定时任务 |
| 配置层 | 控制面板（轻量 Web） | 全部运行参数可视化配置 |

## 4. 核心业务流程

### 4.1 主流程（端到端）

```
[每日 08:00 定时触发（时间可人工配置）]
        │
        ▼
┌─ ① 热点抓取 ──────────────────────────────────────────┐
│ 微信热文：优先第三方 API（用户已授权），无权限则爬虫兜底   │
│ 抖音热点：优先第三方 API（用户已授权），无权限则爬虫兜底   │
│ 按控制面板配置：数据源多选 / 抓取范围 / 抓取字段 / 抓取量  │
│ 写入热点池 + 同步沉淀至本地知识库                        │
└───────────────────────────────────────────────────────┘
        │
        ▼
┌─ ② 热点分析归纳 ──────────────────────────────────────┐
│ 清洗：去重、去广告、去无关内容                           │
│ 聚类：按主题关键词聚合（如"大模型""自动驾驶""芯片"）      │
│ 评分：按控制面板配置的公式参数计算综合热度               │
│ 产出：当日热点归纳报告（Top 主题 + 建议选题 + 简述）      │
└───────────────────────────────────────────────────────┘
        │
        ▼
┌─ ③ 文章生成 ──────────────────────────────────────────┐
│ 从归纳报告选择主题（默认 Top1，可人工指定）               │
│ 人工/自动选择模板与文章结构（加载模板时可随时切换）        │
│ 组装 Prompt → 调用 LLM（默认 qwen3.6-plus）→ 生成        │
│ 校验：字数 / 结构 / 敏感词                              │
│ 校验失败 → 重新生成，受熔断机制约束（最多 N 次后规则兜底）  │
└───────────────────────────────────────────────────────┘
        │
        ▼
┌─ ④ 草稿推送 ──────────────────────────────────────────┐
│ 浏览器自动化登录公众号平台（session 复用 / 扫码重登）      │
│ 新建图文 → 填入标题 / 作者 / 正文 → 保存草稿             │
│ 记录草稿链接与状态；失败自动重试，超限触发熔断            │
└───────────────────────────────────────────────────────┘
        │
        ▼
┌─ ⑤ 人工审核与发布 ────────────────────────────────────┐
│ 审核操作台：热点归纳 + 生成稿件 + 草稿链接               │
│ 通过 → 人工前往公众号平台手动发布（Agent 不代发）        │
│ 驳回 → 附原因，Agent 重新生成（受熔断约束）              │
│ 修改 → 人工在草稿箱直接编辑                             │
└───────────────────────────────────────────────────────┘
```

**每个环节执行前写入断点快照；任一环节失败后可断点续跑，全过程日志可回溯。**

### 4.2 状态机（稿件生命周期）

```
抓取中 → 已入库 → 分析中 → 已归纳
                         │
                         ▼
                    生成中 → 已生成 → 推送中 → 已推送(草稿)
                                         │
                                         ▼
                                    待审核 ──通过──▶ 待发布（人工发布）
                                       │  │
                                       │  └─驳回──▶ 重新生成（熔断约束）
                                       └─修改意见──▶ 待人工编辑
```

### 4.3 触发方式与定时任务

| 方式 | 说明 | 配置方式 |
|------|------|---------|
| 每日定时 | 默认 08:00 抓取、08:30 生成、09:00 推送草稿 | 控制面板以 cron 表达式自定义 |
| **人工设计定时任务** | 支持新增/修改/停用多个定时任务（如"每 6 小时抓取热点""每周一生成周报选题"） | 控制面板 → 定时任务管理，cron 可视化编辑 |
| 手动一键触发 | 操作台"立即运行"，可指定只跑某环节 | 操作台按钮 |
| 失败自动重试 | 失败自动重试，次数受熔断机制约束 | 全局配置 |

## 5. 详细功能需求

### 5.1 热点抓取模块

#### 5.1.1 数据源接入模式（双模式）

| 模式 | 说明 | 前提 |
|------|------|------|
| **API 模式（优先）** | 调用第三方数据服务 API（如新榜、清博、抖音开放平台等） | 用户在控制面板**自行输入 API 授权信息**（key/secret/账号凭据），系统保存并验证可用性 |
| **爬虫模式（兜底）** | 对公开页面进行抓取（Playwright/requests） | 无需授权；受频率限制与反爬约束 |

**权限策略**：API 授权信息**完全由用户自行输入与维护**。系统不代为申请权限；未配置 API 或验证失败时，自动降级为爬虫模式，并给出提示。

#### 5.1.2 微信热文抓取

| 需求项 | 详细说明 |
|--------|---------|
| 数据来源 | API 模式（用户授权）优先；无权限则公开页面爬取兜底 |
| 抓取范围 | 科技/AI 领域关键词（控制面板可自定义，如"大模型、AI、芯片、自动驾驶、机器人、智能硬件"） |
| 抓取字段 | 标题、公众号名、阅读量、点赞数、发布时间、文章链接、摘要（**字段可在控制面板勾选**） |
| 抓取量 | 每关键词 Top 50（控制面板可调），去重后取热度前 top_n（默认 20） |
| 频率 | 每日 1 次（控制面板可配置为每 6 小时等） |

#### 5.1.3 抖音热点抓取

| 需求项 | 详细说明 |
|--------|---------|
| 数据来源 | API 模式（用户授权）优先；无权限则热榜页面爬取兜底 |
| 抓取范围 | 全榜抓取后按领域关键词过滤，或直接使用科技垂类榜（可自定义） |
| 抓取字段 | 热点标题、热度值、排名、话题标签、视频播放量 |
| 抓取量 | 全榜 Top 100（可调）过滤后保留领域相关前 top_n |
| 频率 | 每日 1 次（可配置） |

#### 5.1.4 数据清洗与入库

- 去除标题重复（MD5 去重）、纯广告内容、无实际信息量的标题党
- 统一字段格式，写入 `hot_topics` 表，**同时沉淀至本地知识库**
- 记录抓取时间、数据源、抓取模式（API/爬虫），支持回溯

### 5.2 热点分析归纳模块

| 需求项 | 详细说明 |
|--------|---------|
| 聚类 | 基于关键词/LLM 语义将热点聚合成主题簇（如"大模型发布""算力芯片"） |
| 主题提炼 | 每个主题簇输出：主题名、相关热点数、代表热点、热度合计 |
| 热度评分 | 评分公式**基于控制面板参数**动态计算（详见 5.2.1） |
| 产出报告 | 当日热点归纳报告：Top5 主题 + 建议选题角度 + 一句话简述（JSON + Markdown 双份） |

#### 5.2.1 热度评分公式（参数化，随控制面板配置变化）

```
综合热度 = 平台热度值 × Σ(来源权重) × 时效衰减因子 × 领域相关度 × 抓取量系数

其中：
  · 平台热度值       ：抓取字段中的热度原始值（如阅读量/热度分）
  · 来源权重         ：微信 / 抖音各自的权重系数（控制面板可调，默认 0.6 / 0.4；
                        若用户在控制面板新增/停用数据源，权重自动归一化重算）
  · 时效衰减因子     ：按抓取时间与发布时间差衰减，半衰期可配置（默认 24h）
  · 领域相关度       ：与领域关键词表的匹配度（命中数 / 长度），0~1
  · 抓取量系数       ：实际抓取条数与配置抓取量的归一化比，防样本不均
```

> 评分公式参数（来源权重、半衰期、权重计算方式等）全部在控制面板可视化调整，调整即时生效并记录版本。

### 5.3 文章生成模块

#### 5.3.1 模板管理（人工设计 → 数据库保存）

| 需求项 | 详细说明 |
|--------|---------|
| 设计方式 | 模板由**人工设计**（JSON 结构化定义），在控制面板的模板编辑器中填写 |
| 入库 | 设计完成后保存至数据库 `templates` 表，支持预览、复制、停用、删除 |
| 文章结构 | 模板内可设计多种"结构方案"（如"事件回顾式""观点评论式""盘点清单式"），每个模板可包含多个结构方案，生成时可选择 |
| 生成时选择 | 运行生成流程时，**加载模板的步骤中人工/自动可选**：选择模板 + 选择结构方案，可中途切换（见 5.3.3） |

模板 JSON 示例：

```json
{
  "template_id": "tpl_ai_news_v1",
  "name": "AI 领域热点解读",
  "scene": "热点解析类",
  "structures": [
    {
      "structure_id": "s1",
      "name": "事件回顾式",
      "sections": [
        {"key": "title", "desc": "标题，含核心关键词，20字内，生成3个候选"},
        {"key": "lead", "desc": "导语 80~120 字，点明热点+读者价值"},
        {"key": "body", "desc": "正文 1200~1800 字，分 3~4 小节：事件回顾/影响分析/观点"},
        {"key": "quote", "desc": "金句 1 句，可引用行业观点"},
        {"key": "cta", "desc": "结尾引导 50~80 字，引导点赞/转发/关注"}
      ]
    },
    {
      "structure_id": "s2",
      "name": "盘点清单式",
      "sections": [
        {"key": "title", "desc": "标题，如《2026 值得关注的 5 大 AI 事件》"},
        {"key": "lead", "desc": "导语说明盘点背景"},
        {"key": "body", "desc": "正文按条目盘点，每条 150~250 字"},
        {"key": "cta", "desc": "结尾引导互动"}
      ]
    }
  ],
  "style": {"tone": "专业但不晦涩", "persona": "科技观察者", "ban_words": ["绝对", "最", "第一"]}
}
```

#### 5.3.2 生成流程

1. 选定主题（默认 Top1，可人工指定）
2. **选择模板 + 文章结构方案**（默认模板由控制面板指定，运行时可更改）
3. 加载模板 + 热点数据 + 知识库相关素材（可选：LLM 补充背景）
4. 组装 Prompt（角色、任务、结构、字数、风格、示例）
5. 调用 LLM 生成（默认通义千问 qwen3.6-plus，模型可在控制面板切换）
6. 结构化解析输出，保存至 `articles` 表

#### 5.3.3 质量校验与熔断（防无限重复）

| 校验项 | 规则 | 不通过处理 |
|--------|------|-----------|
| 字数 | 正文在模板区间 ±20% | 重新生成（受熔断约束） |
| 结构 | 各章节齐全 | 重新生成（受熔断约束） |
| 敏感词 | 命中违禁词表 | 人工标记，转审核拦截 |
| 事实性 | 含"据/报道"等来源标识提示人工核实 | 仅提示，不阻断 |

**熔断规则（全局）**：

- 单次生成失败重试上限：**默认 3 次**（控制面板可调）
- 超过上限：**停止自动重试，触发规则兜底** —— 自动标记该稿件为"生成失败"，记录失败原因，改由**人工指定调整方向后重试**或采用"备选结构方案/备选模板"降级生成一次
- 同一热点累计生成失败 ≥ 5 次：该热点自动进入黑名单，当日不再尝试

### 5.4 草稿推送模块（关键：个人订阅号方案）

> **背景**：个人订阅号（未认证）无官方开放平台 API 权限，无法调用 `draft/add` 接口。本模块采用 **Playwright 浏览器自动化** 实现草稿创建。

| 需求项 | 详细说明 |
|--------|---------|
| 登录方式 | 首次：启动浏览器打开 mp.weixin.qq.com，人工扫码登录；登录后保存 `storage_state.json` 复用会话 |
| 会话管理 | 每次操作前校验会话有效性；失效则弹窗提示扫码，Agent 暂停等待 |
| 草稿创建 | 进入"草稿箱 → 新的创作 → 图文消息"，自动填入标题、作者、正文 |
| 正文格式 | Markdown 转富文本（加粗、小标题、引用、列表保留） |
| 封面图 | 一期留空（保留扩展能力：预留封面图选取接口，二期接入） |
| 保存动作 | 点击"保存为草稿"，确认后记录草稿链接 |
| 结果回执 | 成功：记录草稿链接与创建时间；失败：截图留证 + 标记推送失败，重试受熔断约束 |
| 风控保护 | 单日草稿上限（默认 5 篇）、操作间隔随机化（2~5 秒）、失败即停 |

**备选/兜底方案**：

| 方案 | 说明 | 适用 |
|------|------|------|
| A. Playwright 自动化（主方案） | 全自动创建草稿 | 日常使用 |
| B. 半自动粘贴 | Agent 生成内容 → 人工粘贴到草稿箱 | 自动化被风控时兜底 |
| C. 升级认证 | 升级为认证订阅号/服务号，改用官方 API | 长期演进方向，接口稳定 |

### 5.5 人工审核与发布模块

| 需求项 | 详细说明 |
|--------|---------|
| 审核操作台 | 轻量 Web 页面：当日热点归纳报告、生成稿件全文、草稿链接、来源热点 |
| 审核动作 | 通过 / 驳回（附原因）/ 返回修改意见 |
| 发布 | **Agent 不自动发布**。审核通过后由人工打开草稿箱确认发布；Agent 记录"已发布"状态 |
| 审核记录 | 全量记录（操作人、时间、结果、备注），可追溯 |
| 驳回重生成 | 驳回时携带原因，Agent 基于原因 + 原稿重新生成（受熔断约束） |

### 5.6 控制面板（配置中心）—— 本期核心

| 配置分组 | 配置项 | 说明 | 默认值 |
|---------|--------|------|--------|
| **数据来源** | 可用数据源多选（微信热文 / 抖音热点） | 限定范围内勾选启用 | 微信+抖音均启用 |
| **抓取范围** | 领域关键词表（自定义增删） | 影响过滤与相关度 | 大模型、AI、芯片等 |
| **抓取字段** | 各数据源抓取字段勾选 | 如标题/阅读量/点赞/链接 | 全选 |
| **抓取量** | top_n、每关键词抓取条数 | 控制热点池规模 | 20 / 50 |
| **频率** | 各源抓取频率 | 每日/每6小时等 | 每日 1 次 |
| **评分参数** | 来源权重、时效半衰期、相关度开关 | 影响热度评分公式 | 0.6/0.4、24h、开 |
| **模板** | 默认模板、模板库管理（设计/编辑/启停/删除） | 含文章结构方案管理 | tpl_ai_news_v1 |
| **调度** | 定时任务增删改（cron 表达式） | 人工自定义任务 | 每日 08:00 等 |
| **账号** | 公众号 session、API 授权信息（用户自填） | 加密存储 | 空 |
| **LLM** | 模型、temperature、max_tokens | 可切换供应商 | qwen3.6-plus / 0.7 / 2000 |
| **熔断** | 各环节重试上限、热点黑名单阈值 | 全局防失控 | 3 次 / 5 次 |
| **知识库** | 清理策略（去重/过时/低价值规则与周期） | 见 5.7 | 每周清理 |

控制面板基于**轻量 Web**（FastAPI + 简单前端），所有配置即时生效并记录变更日志。

### 5.7 本地知识库管理

| 需求项 | 详细说明 |
|--------|---------|
| 留存 | 每次抓取的热文**完整保留**（标题、链接、摘要、正文片段、来源、时间、热度），写入知识库表 |
| 用途 | 选题参考、历史热点回溯、生成文章时的素材补充 |
| **定期清理** | 按配置的清理策略（默认每周）执行： |
| 清理规则 1：主题重复 | 相似度聚类（标题/摘要文本相似度 ≥ 阈值）去重，保留热度最高的一条 |
| 清理规则 2：过时 | 发布时间超过保留期限（默认 30 天，可配置）自动归档/删除 |
| 清理规则 3：低价值 | 热度低于阈值、无阅读数据、纯广告类内容直接清理 |
| 清理审计 | 清理动作全量记录日志（清理条目、原因、时间），可回溯可恢复 |

### 5.8 断点保留与流程可回溯

| 需求项 | 详细说明 |
|--------|---------|
| 断点写入 | 每个环节开始前/结束后写入状态快照（环节名、输入输出摘要、状态、时间戳）至 `run_logs`/`checkpoints` 表 |
| 断点续跑 | 流程中断（崩溃/重启/手动中止）后，可从最后一个成功断点继续，不重复执行已完成环节 |
| 全流程回溯 | 任意稿件可回溯完整链路：热点来源 → 抓取记录 → 归纳报告 → 生成请求/响应 → 校验结果 → 推送结果 → 审核记录 |
| 展示 | 控制面板提供运行历史列表，点击查看任意一次运行的全链路详情 |

## 7. 数据模型设计（核心表）

```sql
-- 热点表（热点池 + 知识库留存）
CREATE TABLE hot_topics (
  id INTEGER PRIMARY KEY,
  source TEXT NOT NULL,              -- wechat / douyin
  fetch_mode TEXT,                   -- api / crawler
  title TEXT NOT NULL,
  url TEXT,
  platform_hot REAL,
  author TEXT,
  summary TEXT,
  category TEXT,
  heat_score REAL,
  fetch_date TEXT NOT NULL,
  created_at TEXT DEFAULT (datetime('now'))
);

-- 稿件表
CREATE TABLE articles (
  id INTEGER PRIMARY KEY,
  topic_id INTEGER REFERENCES hot_topics(id),
  template_id TEXT NOT NULL,
  structure_id TEXT,                 -- 选用的文章结构方案
  title TEXT NOT NULL,
  lead TEXT, body TEXT, quote TEXT, cta TEXT,
  status TEXT DEFAULT 'generated',
  draft_url TEXT,
  reject_reason TEXT,
  fail_count INTEGER DEFAULT 0,      -- 失败次数（熔断计数）
  created_at TEXT DEFAULT (datetime('now'))
);

-- 模板表（人工设计入库）
CREATE TABLE templates (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  definition TEXT NOT NULL,          -- JSON（含 structures 数组）
  enabled INTEGER DEFAULT 1,
  updated_at TEXT
);

-- 配置表（控制面板，含评分参数）
CREATE TABLE configs (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,               -- JSON
  updated_at TEXT,
  updated_by TEXT
);

-- 定时任务表（人工设计）
CREATE TABLE schedules (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  cron TEXT NOT NULL,
  actions TEXT NOT NULL,             -- 要执行的环节
  enabled INTEGER DEFAULT 1
);

-- 断点/运行日志表
CREATE TABLE run_logs (
  id INTEGER PRIMARY KEY,
  run_id TEXT NOT NULL,              -- 一次完整流程的 ID
  stage TEXT NOT NULL,               -- fetch/analyze/generate/push/review
  status TEXT NOT NULL,              -- success/failed/checkpoint
  detail TEXT,
  started_at TEXT, finished_at TEXT
);

-- 知识库清理日志表
CREATE TABLE kb_clean_logs (
  id INTEGER PRIMARY KEY,
  topic_id INTEGER,
  clean_type TEXT,                   -- dup/outdated/low_value
  reason TEXT,
  cleaned_at TEXT
);
```

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 公众号平台风控（自动化操作被检测） | 账号受限/封禁 | 频率控制、间隔随机化、失败即停、熔断、保留人工兜底方案 B |

| 自动化无限重复（死循环） | 资源浪费/异常堆叠 | **全局熔断机制**：重试上限 + 超限规则兜底 + 热点黑名单 |

| 知识库膨胀 | 存储膨胀/检索噪音 | 定期清理策略（去重/过时/低价值）+ 清理日志可回溯 |
| session 过期/扫码障碍 | 推送中断 | 会话有效期检测 + 登录提醒机制 |
| 配置误操作 | 抓取异常/评分失真 | 配置变更日志 + 参数版本记录 + 默认值保护 |

## 11. 验收标准

1. **抓取**：按控制面板配置（数据源多选、抓取范围、字段、量、频率）成功抓取并入库，API 未授权时自动降级爬虫且数据完整
2. **归纳**：输出热点归纳报告，评分结果随评分参数调整而正确变化（可验证公式）
3. **生成**：模板可由人工设计并保存入库；生成时可选择模板与结构方案；稿件结构完整、字数达标、无敏感词
4. **熔断**：人为制造连续失败，验证重试到上限后自动停止并按规则兜底（不无限重复）
5. **推送**：稿件自动出现在草稿箱，标题/正文格式正确，记录草稿链接
6. **审核**：操作台可查看、通过、驳回；驳回后重新生成且受熔断约束
7. **知识库**：热文留存完整；触发清理策略后重复/过时/低价值内容被清理且有日志
8. **断点**：模拟流程中断后重启，可从断点续跑，全链路可回溯
9. **稳定**：连续运行 7 天无人工干预（除审核与扫码外）全流程正常
